# Windows 环境飞书推送故障排除指南

## 问题描述

在 Windows 环境中配置飞书群组并发送测试消息时，可能出现以下错误：

```
请求失败：SyntaxError: Unexpected token < in JSON at position 0
```

## 原因分析

这个错误表示程序收到的响应是 HTML 而不是 JSON，通常由以下原因导致：

1. **SSL/TLS 证书验证失败** - Windows 环境可能缺少最新的根证书
2. **网络代理或防火墙拦截** - 企业网络可能拦截 HTTPS 请求
3. **Python SSL 证书包过期** - certifi 包的证书可能过旧

## 解决方案

### 方案 1：禁用 SSL 证书验证（快速测试）

⚠️ **警告：** 此方法仅用于调试，不推荐在生产环境使用。

1. **创建环境变量文件**
   在 exe 同级目录创建 `.env` 文件（如果不存在）：
   ```env
   FEISHU_VERIFY_SSL=false
   ```

2. **重启应用**
   关闭并重新运行 `BOSS直聘管理工具.exe`

3. **测试消息**
   再次尝试发送测试消息

### 方案 2：更新 Windows 证书（推荐）

1. **更新 Windows 根证书**
   - 打开 Windows Update
   - 检查并安装所有可用更新
   - 特别注意"证书更新"相关的更新

2. **导入飞书证书**
   - 访问 https://open.feishu.cn
   - 点击浏览器地址栏的锁图标
   - 导出证书到本地
   - 双击证书文件，选择"安装证书"
   - 选择"受信任的根证书颁发机构"

3. **重启应用测试**

### 方案 3：配置网络代理（企业环境）

如果您的网络使用代理，需要配置代理设置：

1. **创建 .env 文件**
   ```env
   HTTP_PROXY=http://proxy.example.com:8080
   HTTPS_PROXY=http://proxy.example.com:8080
   FEISHU_VERIFY_SSL=true
   ```

2. **替换代理地址**
   将 `proxy.example.com:8080` 替换为实际的代理地址

3. **重启应用**

### 方案 4：使用详细日志诊断

如果上述方案无效，启用详细日志来诊断问题：

1. **查看控制台输出**
   运行 exe 时，控制台会显示详细的错误信息，包括：
   - 响应状态码
   - 响应头
   - 响应内容前 500 字符

2. **根据日志判断问题**
   - 如果状态码是 000：网络连接失败
   - 如果状态码是 400/401：配置有误（app_id/app_secret）
   - 如果状态码是 500/502/503：飞书服务暂时不可用
   - 如果响应内容包含 HTML：SSL 或代理问题

## 常见错误代码

| 错误现象 | 可能原因 | 解决方案 |
|---------|---------|---------|
| `SyntaxError: Unexpected token <` | SSL 证书验证失败 | 方案 1 或 2 |
| `Connection timeout` | 网络不通或被防火墙拦截 | 检查网络连接，配置代理 |
| `Code: 9999` | app_id 或 app_secret 错误 | 检查配置，重新输入 |
| `Code: 0, Msg: ok` 但未收到消息 | chat_id 不正确 | 确认群组 ID 是否正确 |

## 获取正确的群组 ID

1. **在飞书中打开群聊**
2. **点击群聊设置**
3. **查看群信息**
4. **复制群 ID**（格式类似 `oc_xxxxxxxxxxxxxxxx`）
5. **粘贴到应用的飞书配置中**

## 开发环境 vs 生产环境

| 环境 | SSL 验证 | 代理配置 |
|-----|---------|---------|
| Mac 开发环境 | ✅ 正常工作 | ✅ 自动检测 |
| Windows 生产环境 | ❌ 可能失败 | ❌ 需要手动配置 |

## 推荐配置

**生产环境配置（.env）：**
```env
# SSL 证书验证（生产环境必须启用）
FEISHU_VERIFY_SSL=true

# 网络代理（如果需要）
# HTTP_PROXY=http://proxy.example.com:8080
# HTTPS_PROXY=http://proxy.example.com:8080
```
